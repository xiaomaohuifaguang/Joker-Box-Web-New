# components/process-flow — 流程图共享件（设计器 + 前台预览共用）

流程引擎画布的跨端共享层：后台流程设计器（`app/console/process-manager/designer/`）与前台流程预览（申请/审批中心实例页「流程预览」弹窗）共用同一套节点渲染与 rawData 转换。

- `nodes.tsx`：节点体系——`ProcessNodeKind`/`ProcessNodeData`/`ProcessEdgeData` 类型、`PROCESS_NODE_REGISTRY`（分组/形状/锚点/出入线约束/配色）、三个形状族组件（事件圆/任务矩形/网关菱形）、`processNodeTypes` 注册表。另含编辑交互导出（`processNodeContextHandler`/`hitEdgeIdAt`/`APPLY_NODE`/`PROCESS_NODE_LIST`/`nextKindLabel`），仅设计器用。
- `flow-utils.ts`：rawData（`ProcessRawData` = React Flow `{nodes, edges}`，见 `types/process.ts`）→ nodes/edges 的纯函数转换（`nodesFromRaw`/`edgesFromRaw`/`createEdge`/`pickGatewaySourceHandle`/`nodeSizeFor`）+ 边色常量与 `edgeColors(isDark)`。**反方向**（保存路径 stripNode/stripEdge/buildRawData）留在设计器。边色用具体 hex 不用 CSS 变量——SVG path/marker 解析不到 `:root` 上的 var；明/暗靠 `hooks/useIsDark` 切档。
- `ProcessFlowCanvas.tsx`：只读画布（纯展示）：`rawData` + 可选 `track?: ProcessTrack`（流程追踪，见下）。不可拖/连/选，`fitView` 还原持久化的 position（**不重排**），双层 Background + Controls + MiniMap（节点色跟随追踪状态）。自带 `@xyflow/react` 样式 import。**父容器必须显式定高**（如 `h-[70vh]`）。**坑**：受控 `nodes` 且无 `onNodesChange` 时 userNode.measured 永不写回，MiniMap 逐节点门禁不过会整版空白——画布按形状族补 `initialWidth`/`initialHeight`（`initialSizeFor`），详见 CLAUDE.md 通用坑。
- `ProcessTrackRecordsPanel.tsx`：追踪弹窗右侧常驻的处理记录面板（双态，图纸「会签栏」语汇：spine 竖轴 + handleType 语义色签章点——pass=success/auto_pass=info/reject=error/back=warning/to_claim·to_do=primary(当前活动任务，与画布「蓝=当前」同族)/其余 muted，全走主题 token——+ 两行条目：章+人 / mono 时间 / 备注；空字段不渲染占位符，to_claim 无处理人、活动任务无时间）。**未选中节点（默认/点空白/点 X/再点已选中节点）= 流程处理时间线**（`track.processHandleInfoList`，全节点混排，后端已按时间排序，不分轮次；**条目首行=节点名**（taskName，空则 taskDefinitionKey 经 `nodeLabelOf` 查 rawData 节点 label 兜底——混排不靠它分不清记录属于哪个节点），会签栏头部已是节点名故不重复）；**选中节点 = 该节点会签栏**（`track.nodeRoundRecordInfoList[nodeId]`，key=节点 id，>1 轮才有「第 N 轮」发丝线分组）。头部=节点名+类型（REGISTRY label）或「处理时间线」，均带总数徽标。
- `ProcessFlowButtons.tsx`：自包含入口件（按钮组 + Dialog）。「流程预览」常驻（纯图，无追踪叠加）；传 `track` 时追加「流程追踪」按钮（图例 + 高亮 + 记录面板）。两按钮共享一次 `getProcessDefinitionInfo(definitionId, version)` 请求（按 `definitionId|version` 缓存，重复打开不重拉）；`definitionId` 空不渲染；加载 skeleton / 失败重试 / 空数据三态。

**流程追踪契约**：`track` = `ProcessInstance.processTrack`（`types/process.ts`，与 processDefinitionName 同级；`currentNodeId` 仅 info 传 taskId 的处理页返回）。视觉三色（恒定信号色不随预设，`flow.css`）：**绿=已走过**（doneNodeIds 节点 `.flow-node-done` 绿环 / passedEdgeIds 连线绿加粗，走过的默认分支保持虚线变绿）、**蓝=当前**（activeNodeIds `.flow-node-active` glow；currentNodeId 叠加 `.flow-node-current` 脉冲，与并行其余活动节点区分）、**灰=未经过**。节点注入优先级 current > active > done；`__done`/`__current`/`__selected` 与 `__active` 同为运行时字段（`__` 前缀保存时 stripNode 剥离）。弹窗图例随 track 出现，「当前任务」项仅 currentNodeId 存在时显示。

**处理记录（`nodeRoundRecordInfoList`）**：追踪弹窗右侧常驻 `ProcessTrackRecordsPanel`（画布 flex-1 + 面板 md:w-80，窄屏落底部 h-56；面板常驻所以画布宽度不变、不触发 fitView 跳动）。`ProcessFlowCanvas` 新 props `onNodeClick`（再点已选中节点=取消）/`onPaneClick`（空白点击清除选中回时间线）/`clickableNodeIds`/`selectedNodeId`：有记录的节点注入 `cursor-pointer`、选中节点注入 `__selected`（中性 ring，预览画布 `elementsSelectable=false` 走不到 RF 原生 selected）。打开追踪默认落时间线（null 选中）；预览弹窗无面板、布局不变。

约定：实例视图接入走 `ProcessFlowButtons`（`ProcessWorkHeader` 的 `action` 槽位或自定义 header 直插）；version 一律传实例自身的 `processDefinitionVersion`（预览图与实例版本一致，接口不传 version 则取最新）。
